

База данных по умолчанию: default


--------------------------------------------------------------------------------
1. ГЛАВНОЕ
--------------------------------------------------------------------------------

Для большинства интеграций НЕ НУЖНО читать flows_raw напрямую.
Это самая большая raw-таблица.

Для UI, алертов и быстрых проверок сначала использовать агрегаты:

  Задача                              | Рекомендуемая таблица
  ------------------------------------+------------------------------------------
  Общий трафик по направлениям        | traffic_dashboard_1m, 1h, 1d
  Top источники / назначения          | traffic_talker_1m, traffic_talker_1h
  Top пары src -> dst                 | traffic_pair_1m, traffic_pair_1h
  Top протоколы IP                    | traffic_protocol_1m
  Top сервисы / порты                 | traffic_service_1m, traffic_unknown_port_1m
  География / страны                  | traffic_country_1m
  DNS события                         | dns_log, dns_answers
  Справочник наших сетей            | net_l3_prefixes_enabled
  Справочник источников данных        | net_flow_sources_enabled


--------------------------------------------------------------------------------
2. НАПРАВЛЕНИЯ ТРАФИКА (поле direction)
--------------------------------------------------------------------------------

Поле direction уже рассчитано в xdpflowd и записано в таблицы.

  Значение    | Что значит
  ------------+------------------------------------------------------------------
  in          | внешний источник -> наша/клиентская сеть
  out         | наша/клиентская сеть -> внешний получатель
  internal    | наша/клиентская сеть -> наша/клиентская сеть
  transit     | внешний источник -> внешний получатель через нас
  unknown     | направление не удалось определить

В UI может быть режим «Всего», но в ClickHouse НЕТ direction = 'total'.

Для «Всего» использовать:

  direction IN ('in', 'out', 'transit', 'internal', 'unknown')


--------------------------------------------------------------------------------
3. RAW FLOW
--------------------------------------------------------------------------------

Таблица: flows_raw
-----------------
Главная raw-таблица flow-событий. Очень большая.
Использовать только когда агрегатов недостаточно.

  Поле                  | Назначение                          | Где используется
  ----------------------+-------------------------------------+----------------------------------
  time_received_ns      | время получения flow                | фильтр периода, агрегаты
  src_addr, dst_addr    | IP source/dest (бинарный вид)         | drill-down, IP-агрегаты
  src_asn, dst_asn        | origin ASN для IP                   | ASN/GEO, top talkers
  direction             | направление трафика                 | все dashboard/top таблицы
  src_endpoint_scope    | чей IP: local/customer/remote/...   | DDoS: внешний/наш endpoint
  dst_endpoint_scope    | то же для destination               | DDoS: цель/источник
  src_network_name      | имя сети/префикса из справочника     | владелец/сеть
  dst_network_name      | то же                               | владелец/сеть
  src_network_role      | роль сети (local, customer, ...)      | классификация
  dst_network_role      | то же                               | классификация
  src_label, dst_label  | подпись endpoint (DNS/name)         | UI, drill-down
  proto                 | номер IP-протокола                  | protocol analytics
  src_port, dst_port    | порты                               | service/port analytics
  bytes, packets        | объём flow                          | все метрики
  source_id             | источник наблюдения (зеркало и т.п.)  | фильтр, anti double-count


--------------------------------------------------------------------------------
4. ИСТОЧНИКИ ДАННЫХ
--------------------------------------------------------------------------------

Таблицы: net_flow_sources, net_flow_sources_enabled (view)
----------------------------------------------------------------
Справочник источников трафика: XDP, NetFlow, IPFIX, sFlow, DNS и т.п.

  Поле              | Назначение                    | Где используется
  ------------------+-------------------------------+----------------------------------
  source_id         | ID источника (xdp-default)    | join/filter во всех агрегатах
  display_name      | название для UI               | фильтр источников
  source_type       | xdp, netflow, dns, ...        | UI, операционные проверки
  include_in_total  | включать в total или нет      | dashboard, DDoS по умолчанию
  enabled           | активен ли источник           | soft-delete

Типичный join для default-запросов:

  INNER JOIN default.net_flow_sources_enabled AS s
    ON t.source_id = s.source_id
  WHERE s.include_in_total = 1

5. СПРАВОЧНИКИ СЕТИ

Таблицы: net_entities, net_entities_enabled

Объекты сети: клиент, узел, аплинк, наша инфраструктура.

Таблицы: net_l3_prefixes, net_l3_prefixes_enabled
------------------------------------------------

  Поле          | Назначение                              | Где используется

  prefix        | IP-префикс                              | classifier
  family        | IPv4 / IPv6                             | classifier
  entity_id     | владелец/объект сети                    | UI, отчёты

                | customer_allocated, customer_transit    |
  display_name  | название префикса                       | labels, drill-down
  enabled       | активен ли префикс                      | classifier


Таблицы: net_l2_vlans, net_l2_vlans_enabled
-------------------------------------------
L2/VLAN-контекст: где пакет был увиден (не «чей IP»).

  Поле              | Назначение                          | Где используется
  ------------------+-------------------------------------+----------------------------------

  entity_id         | объект сети                         | UI, аналитика
  attachment_type   | customer, uplink, ix, peering, ...   | где увидели пакет
  boundary          | internal, external, unknown         | диагностика direction
  display_name      | подпись VLAN/линка                  | UI

7. TOP TALKERS (источники / назначения)
--------------------------------------------------------------------------------

Таблицы: traffic_talker_1m, traffic_talker_1h
--------------------------------------------
Top endpoint-ы. Одна flow-запись даёт ДВЕ строки:
  endpoint_side = 'src'  и  endpoint_side = 'dst'

  Поле                        | Назначение                    | Где используется
  ----------------------------+-------------------------------+----------------------------------
  minute / hour               | bucket времени                | период
  source_id                   | источник данных               | фильтр
  endpoint_side               | src или dst                     | Источники / Назначения
  direction                   | in/out/transit/...            | фильтр направления
  endpoint_ip                 | IP                            | top IP
  endpoint_asn, endpoint_as_name| ASN                           | display, filter
  endpoint_ip_country         | страна IP                     | GEO
  endpoint_as_country         | страна ASN (реестр)           | справка
  endpoint_scope              | local/customer/remote/unknown | внешний или наш IP
  endpoint_label              | label / DNS / name            | UI
  endpoint_network_name       | имя сети (если локальный IP)  | атрибуция цели DDoS
  endpoint_network_role       | роль сети                     | атрибуция
  bytes, packets, flows_count | метрики                       | сортировка, детали

Использование (фильтры):

  Задача                              | SQL-фильтр
  ------------------------------------+------------------------------------------
  Топ источников входящего DDoS       | direction='in' AND endpoint_side='src'
  Топ целей входящего DDoS            | direction='in' AND endpoint_side='dst'
  Топ наших исходящих отправителей    | direction='out' AND endpoint_side='src'
  Топ внешних назначений исходящего   | direction='out' AND endpoint_side='dst'

Выбор таблицы по периоду:

  Период        | Таблица
  --------------+---------------------
  до 1 часа     | traffic_talker_1m
  3h / 6h / 12h / 24h+ | traffic_talker_1h

8. TOP PAIRS (пары src -> dst)
--------------------------------------------------------------------------------

Таблицы: traffic_pair_1m, traffic_pair_1h
-----------------------------------------
Самый детальный и самый тяжёлый top-агрегат (много уникальных пар IP).

  Поле                    | Назначение              | Где используется
  ------------------------+-------------------------+----------------------------------
  minute / hour           | bucket                  | период
  source_id               | источник данных         | фильтр
  direction               | направление             | in/out/...
  src_ip, dst_ip          | пара IP                 | вкладка «Пары»
  src_asn, dst_asn        | ASN обеих сторон        | детали
  src_as_name, dst_as_name| названия ASN            | UI
  src_ip_country,         | GEO                     | UI
  dst_ip_country          |                         |
  src_scope, dst_scope    | чей IP (local/remote)   | атакующий / цель
  src_label, dst_label    | подписи                 | UI
  bytes, packets,         | метрики                 | сортировка
  flows_count             |                         |

Для DDoS:

  Задача                              | Подход
  ------------------------------------+------------------------------------------
  Кто атакует какую цель              | direction='in', группировка src_ip->dst_ip
  Какие наши IP шлют наружу           | direction='out', группировка src_ip->dst_ip

Для длинных периодов использовать только traffic_pair_1h (не 1m).

--------------------------------------------------------------------------------
13. РЕКОМЕНДАЦИИ ДЛЯ DDoS-МОДУЛЯ (пошагово)
--------------------------------------------------------------------------------

Быстро определить возможную ВХОДЯЩУЮ атаку:

  1) traffic_dashboard_1m или traffic_dashboard_1h
     -> смотреть рост in_bytes, in_packets

  2) traffic_talker_1m/1h
     -> direction = 'in' AND endpoint_side = 'src'
     -> top внешних источников (атакующие IP)

  3) traffic_talker_1m/1h
     -> direction = 'in' AND endpoint_side = 'dst'
     -> top целей (наши/клиентские IP под атакой)

  4) traffic_pair_1m/1h
     -> direction = 'in'
     -> конкретные связки src_ip -> dst_ip

  5) traffic_protocol_1m, traffic_service_1m, traffic_unknown_port_1m
     -> профиль атаки (UDP flood, DNS, неизвестные порты и т.д.)


Что считать ВНЕШНИМ ИСТОЧНИКОМ (входящий DDoS):

  direction = 'in'
  endpoint_side = 'src'
  endpoint_scope = 'remote'    (поле есть в traffic_talker_*)


Что считать ЦЕЛЬЮ (входящий DDoS):

  direction = 'in'
  endpoint_side = 'dst'

Дополнительно смотреть:
  endpoint_ip
  endpoint_label
  endpoint_network_name
  endpoint_network_role
  endpoint_scope


--------------------------------------------------------------------------------
14. ВАЖНЫЕ ОГОВОРКИ
--------------------------------------------------------------------------------

  * flows_raw огромная — не строить UI/алерты по ней без крайней необходимости.

  * Всегда учитывать source_id и include_in_total (net_flow_sources_enabled),
    чтобы не считать один и тот же трафик дважды с разных зеркал.

  * В ClickHouse нет direction = 'total'.
    «Всего» = сумма in + out + transit + internal + unknown.

  * traffic_pair_* — высокая кардинальность.
    Для длинных периодов использовать traffic_pair_1h, не 1m.

  * IP country и ASN country — разные вещи.
    Для географии атаки обычно использовать IP-country (country_basis = ip).
